Antes de tudo: as 4 regras

  1. Não mexa no projeto taverna-livekit (Caddy e LiveKit). O bot é um projeto separado (-p lovefit-bot), com rede própria, e não sobe outro Caddy.
  2. Nenhuma porta nova é aberta na internet. O painel escuta só em 127.0.0.1:3000. O acesso público passa pelo Cloudflare Tunnel, que é uma conexão de saída.
  3. Segredos só no .env da VPS, nunca no GitHub. Isso vale também para os telefones da blacklist e para a chave da Evolution.
  4. Nunca deixe os dois bots ligados no mesmo número: o cliente receberia resposta dobrada.

0Preparar no seu computador

O código está em https://github.com/DavidSantanaks/painel-love-fit (público). Para mandar alterações futuras, na pasta do projeto:

npm test                       # 48 testes devem passar
git status                     # .env, backups/ e data/ NÃO podem aparecer
git add -A && git commit -m "descrição da mudança"
git push
  • No n8n que está rodando, exporte o workflow vivo e copie a lista de blacklist (6 números, um repetido) para um arquivo seu, fora do repositório. Não use o gym-chatbot-workflow.json antigo da pasta: ele está desatualizado.
  • O bot antigo continua ligado no ksserver até o passo 12.

1Entrar na VPS

ssh root@IP-DA-VPS             # o IP está no painel da Hostinger

2Criar o usuário deploy e proteger o SSH

adduser deploy
usermod -aG docker,sudo deploy
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/ 2>/dev/null
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys

Em outro terminal, teste antes de fechar o atual:

ssh deploy@IP-DA-VPS
docker ps                      # precisa listar os containers do Taverna, sem erro de permissão
sudo -v                        # sudo precisa funcionar ANTES de desligar o root

Funcionou? Então desligue o login por senha e o login de root:

sudo nano /etc/ssh/sshd_config
#   PasswordAuthentication no
#   PermitRootLogin no
sudo systemctl restart ssh
Não feche o terminal antigo até confirmar que um novo ssh deploy@… entra. Não ative o ufw sem checar as portas do LiveKit. Se quiser firewall, use o do painel da Hostinger e libere SSH e as portas que o Taverna já usa. O bot não precisa de nenhuma porta de entrada.

3Conferir o que já está rodando

docker --version && docker compose version     # Compose v2 é obrigatório
docker ps --format 'table {{.Names}}\t{{.Ports}}'
ss -tulpn | grep -E ':(80|443|3000|8080)\b'
free -h && df -h /

A porta 3000 precisa estar livre em 127.0.0.1. Se não estiver, use outra no .env (PANEL_PORT=3010). O túnel não depende dessa porta, porque fala com o app pela rede interna.

4Baixar o projeto

O repositório é público, então o clone não precisa de chave nem de token:

sudo mkdir -p /opt/lovefit-bot && sudo chown deploy:deploy /opt/lovefit-bot
cd /opt/lovefit-bot
git clone https://github.com/DavidSantanaks/painel-love-fit.git .
Repositório público: o .env, os backups e os telefones da blacklist nunca podem ir para o Git (o .gitignore já bloqueia .env, backups/ e data/). Antes de cada git push, confira com git status.

Se o repositório ficar privado

O git pull na VPS passa a pedir login. Crie uma deploy key (chave só de leitura, válida só para este repositório):

ssh-keygen -t ed25519 -C "lovefit-vps" -f ~/.ssh/lovefit_deploy -N ""
cat ~/.ssh/lovefit_deploy.pub
# GitHub → painel-love-fit → Settings → Deploy keys → Add deploy key
# cole a chave e NÃO marque "Allow write access"

cat >> ~/.ssh/config <<'CFG'
Host github-lovefit
  HostName github.com
  User git
  IdentityFile ~/.ssh/lovefit_deploy
  IdentitiesOnly yes
CFG
chmod 600 ~/.ssh/config

cd ~/painel-love-fit                # ou /opt/lovefit-bot
git remote set-url origin github-lovefit:DavidSantanaks/painel-love-fit.git
ssh -T github-lovefit               # responda "yes" na 1ª vez; deve dizer "successfully authenticated"
git pull                            # deve funcionar sem pedir senha

5Criar o .env com segredos novos

cd /opt/lovefit-bot
cp .env.example .env
for v in AUTHENTICATION_API_KEY POSTGRES_PASSWORD WEBHOOK_TOKEN SESSION_SECRET; do
  sed -i "s|^$v=.*|$v=$(openssl rand -hex 32)|" .env
done
chmod 600 .env
nano .env                      # confira; TUNNEL_TOKEN vem no passo 6
VariávelValor na VPS
COMPOSE_PROFILEStunnel (sobe o cloudflared)
AUTHENTICATION_API_KEYgerada. Nova: não reaproveite a chave do bot antigo.
POSTGRES_PASSWORD, WEBHOOK_TOKEN, SESSION_SECRETgerados pelo comando acima
TUNNEL_TOKENtoken do túnel (passo 6)
TIMEZONEAmerica/Sao_Paulo
PANEL_PORT3000 (só em 127.0.0.1)
RCLONE_REMOTE (opcional)destino do backup fora da VPS (passo 13), ex.: gdrive:lovefit-backups
Guarde uma cópia do .env no seu gerenciador de senhas. Sem a POSTGRES_PASSWORD, os backups continuam restauráveis, mas você precisa dela para subir o stack de novo.

6Criar o túnel no Cloudflare

  1. Cloudflare One → Networking → Tunnels → criar túnel, do tipo Cloudflared.
  2. Nome: lovefit-bot. Na tela de instalação, copie só o token (o texto longo depois de --token) e cole em TUNNEL_TOKEN= no .env. Não rode o comando de instalação que o Cloudflare sugere: o cloudflared já está no compose.
  3. Abra o túnel lovefit-bot → aba Routes → Add route → Published application:
    CampoValor
    Subdomainpainellovefit
    Domaintavernahub.com.br
    Path(vazio)
    Service URLhttp://app:3000
  4. Confira se o Domain escolhido é mesmo tavernahub.com.br, porque o dropdown lista todos os domínios da conta. Save. O Cloudflare cria o CNAME sozinho. Não crie registro DNS à mão, e confira em DNS que não existe um painellovefit antigo. O registro lk do LiveKit fica como está.
Recomendado: faça o passo 9 (Cloudflare Access) antes de salvar esta rota, para o painel nunca ficar exposto sem a camada de e-mail. Se seguir a ordem do guia, deixe o intervalo entre os dois passos o mais curto possível.

7Subir os containers

cd /opt/lovefit-bot
./manage.sh up                 # valida o .env e roda: docker compose -p lovefit-bot up -d --build

A primeira vez demora de 3 a 6 minutos (build da imagem do app). Depois:

docker compose -p lovefit-bot ps            # todos "Up"; app e postgres "(healthy)"
curl -s http://127.0.0.1:3000/api/health    # {"ok":true}
docker compose -p lovefit-bot logs app --tail 30
docker stats --no-stream                    # o bot deve usar cerca de 1 a 2 GB no total
docker ps | grep -Ei 'caddy|livekit'        # o Taverna continua de pé
No log do app devem aparecer All migrations have been successfully applied, Seed: franquia LOVE FIT criada com as telas iniciais e worker_started. A migração e o seed rodam sozinhos.

8Criar o admin e abrir o painel

docker compose -p lovefit-bot exec app npm run create-admin -- --email voce@exemplo.com --name "Seu Nome"

Digite em uma linha só. Se colar com \ no meio da linha, o --email não é reconhecido.

Para escolher a senha em vez de usar a gerada (mínimo 12 caracteres, com maiúscula, minúscula e número):

docker compose -p lovefit-bot exec -e PASSWORD='SuaSenhaForte2026' app npm run create-admin -- --email voce@exemplo.com --name "Seu Nome"

A senha aparece uma única vez. Guarde no gerenciador de senhas. Para a recepção (acesso a telas, conversas, configurações e simulador, sem WhatsApp e sem blacklist):

docker compose -p lovefit-bot exec app npm run create-admin -- --email recepcao@exemplo.com --name "Recepção" --role RECEPTION

Rodar o mesmo comando com um e-mail que já existe gera uma senha nova (serve para "esqueci a senha"). Abra https://painellovefit.tavernahub.com.br e entre.

Sem o túnel, por SSH (plano B para a equipe técnica): ssh -L 3000:localhost:3000 deploy@IP-DA-VPS e abra http://localhost:3000.

9Proteger com Cloudflare Access (recomendado)

O Cloudflare passa a pedir um código enviado por e-mail antes de mostrar a tela de login do painel. O painel no Cloudflare agora se chama Cloudflare One (o antigo Zero Trust), e os menus mudaram de lugar.

O ideal é fazer este passo antes de publicar a rota do túnel (passo 6), porque sem o Access o painel fica aberto para qualquer pessoa na internet, protegido só pelo login do app. Se o túnel já está no ar, faça agora mesmo.

9.1 Ligar o login por código de e-mail (One-time PIN)

  1. Cloudflare One → Integrations → Identity providers.
  2. Em Your identity providers, veja se One-time PIN já aparece. Se não aparecer: Add new identity provider → One-time PIN → salvar.

9.2 Criar a política de quem pode entrar

  1. Access controls → Policies → Add a policy.
  2. Policy name: Equipe painel LOVE FIT.
  3. Action: Allow.
  4. Session duration: 24 hours (ou o que preferir).
  5. Em Rules, numa regra do tipo Include: selector Emails e, no valor, o seu e-mail e o de cada pessoa que usa o painel.
  6. Save.

9.3 Criar a aplicação do painel

  1. Access controls → Applications → Create new application.
  2. Escolha Self-hosted and private.
  3. Nome da aplicação: Painel LOVE FIT.
  4. Add public hostname: subdomain painellovefit, Domain tavernahub.com.br, path vazio.
  5. Em Access policies, selecione a política Equipe painel LOVE FIT criada no 9.2. O novo construtor também permite criar a política ali mesmo, sem sair da tela.
  6. Nos provedores de login (identity providers), deixe marcado só One-time PIN. Com um único provedor, pode ligar Apply instant authentication, que pula a tela de escolha do provedor.
  7. Session Duration: 24 hours.
  8. Não precisa mexer em Additional settings.
  9. Create.

9.4 Testar

  • Abra https://painellovefit.tavernahub.com.br numa janela anônima. Deve aparecer a tela do Cloudflare pedindo o e-mail.
  • Digite um e-mail autorizado: chega um código de 6 dígitos. Depois do código, aparece a tela de login do painel.
  • Digite um e-mail que não está na lista: o Cloudflare não libera o acesso.
  • O bot continua respondendo no WhatsApp. O webhook é interno (Evolution → app:3000) e não passa pelo Access.

Para incluir ou tirar alguém depois: Access controls → Policies → Equipe painel LOVE FIT → edite os e-mails → Save. Vale para a aplicação na hora.

Os nomes dos botões seguem a documentação atual do Cloudflare One. Se algum rótulo estiver um pouco diferente na sua tela, o caminho é o mesmo: Access controls → Policies para a política e Access controls → Applications para a aplicação.

10Configurar o painel (antes de conectar números reais)

  1. Telas e menus: revise todas as telas. Textos marcados com [EDITAR] precisam ser preenchidos: preço do plano Básico, regras dos planos, chaves Pix de Atalaia e Jardim Santana e link do cadastro. A pré-visualização à direita mostra como fica no WhatsApp.
  2. Blacklist (menu Blacklist): cole os 6 números do n8n vivo, um por linha, com o rótulo "Família". Qualquer formato serve, e a versão com e sem o 9 já é bloqueada. Alternativa por terminal: 
    nano /tmp/bl.txt               # um número por linha
docker compose -p lovefit-bot exec -T app npm run import-blacklist -- --label "Família" < /tmp/bl.txt
shred -u /tmp/bl.txt
  3. Configurações → Números de aviso: cadastre o celular de quem atende (nenhum pode estar na blacklist, e o painel recusa se estiver).
  4. Configurações → Comportamento: confira a pausa (60 min), o anti-flood (5 s) e a mensagem fora do expediente.
  5. Simulador: converse com o bot. Teste oi, 1, 11, 2, 21, 4, 5, menu e "Enviar como a recepção".

11Conectar o WhatsApp e testar (com número de teste)

  1. Menu WhatsApp → + Nova instância: nome técnico atalaia, unidade Atalaia. Repita com santana / Jardim Santana.
  2. Unidade e horários: cadastre o horário de cada unidade (vira {{horarios}} e controla o "fora do expediente").
  3. Primeiro com um chip de teste: clique em Conectar (QR Code) e, no celular de teste, vá em WhatsApp → Aparelhos conectados → Conectar aparelho. O status muda para Conectado.
  4. Em Configurações, clique em Enviar teste nos números de aviso.
  5. De outro celular, mande mensagens para o número de teste e marque:
  • oi → menu com saudação e nome; o indicador "digitando…" aparece antes
  • 1 → planos; 11 → regras; imagem/PDF chegam (se houver)
  • 5 / atendente → contato na fila em Conversas e WhatsApp no número de aviso
  • Responder pelo celular da loja → o bot fica mudo com aquele contato; menu reativa
  • Duas mensagens em menos de 5 s → uma resposta só
  • Mensagem de um número da blacklist → silêncio total (aparece no Log como "blacklist")
  • docker compose -p lovefit-bot restart app durante uma pausa → continua pausado
  • WhatsApp → Desconectar e reconectar pelo QR Code, sem usar o terminal

Terminado o teste, clique em Desconectar na instância de teste (ou exclua e recrie com o nome definitivo).

12Virada: trocar o bot antigo pelo novo

Faça em horário de pouco movimento.

  1. Backup manual na VPS: ./scripts/backup.sh.
  2. No ksserver, pare o bot antigo sem apagar nada: ./manage.sh stop.
  3. Se o número real estiver conectado ao bot antigo, desconecte-o lá (celular → Aparelhos conectados → sair do aparelho antigo).
  4. No painel novo, Conectar (QR Code) em atalaia e santana com os celulares reais.
  5. Teste de ponta a ponta com um celular seu: menu, atendente, aviso, pausa.
  6. Acompanhe por alguns minutos: ./manage.sh logs app e o menu Log e auditoria.
Plano de volta (mantenha por 7 dias, sem apagar o stack antigo): docker compose -p lovefit-bot stop na VPS → reconectar os números no bot antigo → ./manage.sh start no ksserver.

13Backup diário (obrigatório)

O snapshot semanal da Hostinger não basta. O script faz o dump do banco do app, do banco da Evolution (sessões do WhatsApp) e da mídia, e guarda 14 dias em /opt/lovefit-bot/backups.

Cópia fora da VPS com rclone (Google Drive, por exemplo)

sudo apt install -y rclone
rclone config                  # crie um remote chamado "gdrive" (siga o assistente)
echo 'RCLONE_REMOTE=gdrive:lovefit-backups' >> /opt/lovefit-bot/.env

Agendar (como usuário deploy)

crontab -e
# adicione a linha:
30 3 * * * /opt/lovefit-bot/scripts/backup.sh >> /opt/lovefit-bot/backup.log 2>&1

Testar uma restauração antes de confiar

./scripts/backup.sh
ls backups/                    # ex.: lovefit-20261120-033000.dump
./scripts/restore.sh 20261120-033000      # pede para digitar RESTAURAR
Faça o teste de restauração antes da virada (passo 12), enquanto só existe o número de teste. Em produção, a restauração volta menus, conversas e a sessão do WhatsApp para o momento do backup.

14Atualizar depois

cd /opt/lovefit-bot
./scripts/backup.sh
./manage.sh update             # git pull + docker compose up -d --build (migrações rodam sozinhas)

Mudanças de texto, preço e horário não precisam de deploy: são feitas no painel e valem na hora.

SintomaOnde olhar / o que fazer

Painel não carrega, mas o túnel está conectadoNo log do cloudflared precisa aparecer Updated to new configuration com painellovefit.tavernahub.com.br → http://app:3000. Se não aparecer, a rota não foi salva neste túnel. Se aparecer outro domínio, o domínio errado foi escolhido no dropdown: corrija a rota e apague o CNAME que sobrou na zona errada.
ERR Cannot determine default origin certificate path … cert.pemNormal em túnel com token. Pode ignorar.
Bot não respondePainel → WhatsApp: está "Conectado"? O aviso "Webhook desligado" aparece? Clique em Reconfigurar webhook. Depois: ./manage.sh logs app e ./manage.sh logs evolution-api.
Cliente específico não recebeLog e auditoria: "blacklist", "anti-flood", "pausado" ou "sem telefone resolvido" (contato @lid, ver Configurações).
