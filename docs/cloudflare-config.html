Configuração do Cloudflare — painel LOVE FIT

Registro do que foi configurado no Cloudflare One em 20/11/2026 para publicar e proteger o painel. Não contém o token do túnel nem senhas.
Legenda: ✅ confirmado nos logs ou no teste · ☐ confirmar na tela do Cloudflare e anotar aqui

Como o acesso funciona: navegador → Cloudflare (pede o e-mail e o código, via Access) → túnel lovefit-bot (conexão de saída da VPS) → container cloudflared → http://app:3000 na rede interna do Docker. Nenhuma porta da VPS fica aberta para a internet. O webhook da Evolution (/api/webhooks/evolution) é interno e não passa pelo Cloudflare: o app recusa qualquer chamada a ele que venha do Cloudflare.

6Tarefas comuns

Quero…Onde
Dar acesso a uma pessoa novaAccess controls → Policies → Equipe painel LOVE FIT → adicionar o e-mail em Emails → Save. Depois, criar o login dela no painel (create-admin com --role RECEPTION).
Tirar o acesso de alguémRemover o e-mail da política e trocar ou desativar o usuário no painel.
Ver quem entrouCloudflare One → Logs → Access (autenticações). No painel: Log e auditoria.
Trocar o token do túnel (vazou)Networking → Tunnels → lovefit-bot → refresh/rotate do token → atualizar TUNNEL_TOKEN no .env → docker compose -p lovefit-bot up -d cloudflared.
Tirar o painel do ar rapidamentedocker compose -p lovefit-bot stop cloudflared. O bot continua respondendo no WhatsApp.
Regras que não podem quebrar: (1) não criar registro DNS manual para painellovefit, porque a rota do túnel cuida disso; (2) nunca tirar a política do Access sem outra proteção no lugar; (3) não publicar o webhook nem a Evolution API no túnel: só o painel (app:3000) passa por ele; (4) o token do túnel fica só no .env da VPS.
